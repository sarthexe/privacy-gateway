Variant B MUST:

1. Load existing persisted GLiNER predictions.
2. Select only predictions whose normalized type is DATE_TIME.
3. Keep all original model predictions unchanged.
4. For each DATE_TIME model prediction, inspect only a bounded source neighborhood around the existing model span.
5. Use deterministic structural parsing to determine whether the existing span should have:
   - peripheral punctuation removed
   - legitimate AM/PM retained
   - legitimate timezone suffix retained
   - date/time attachment retained
   - obvious structural punctuation normalized

6. Produce at most ONE refined replacement candidate for an eligible existing DATE_TIME prediction.
7. Never create a DATE_TIME prediction from a source region that has no existing GLiNER DATE_TIME anchor.
8. Never remove an existing model prediction silently.

IMPORTANT:
This is a refinement experiment, not a detector replacement.

STEP 3 — Define anchored eligibility

The candidate must:
- overlap an existing GLiNER DATE_TIME span
- originate from the same source neighborhood
- preserve the semantic/date-time identity implied by the existing model span
- differ only through explicit structural boundary rules

Do NOT:
- expand arbitrarily to surrounding prose
- convert a time into a date+time unless the existing model span already supports that structure
- delete digits to match GT
- remove valid timezone information
- infer missing years/months/dates
- infer relative dates
- infer geographic timezone
- use language or dataset identity
- use GT for eligibility

Ambiguous cases must be rejected and counted.
